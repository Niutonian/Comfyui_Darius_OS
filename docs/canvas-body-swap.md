# Body swap video boards

In Canvas, open a Video board and select **Body swap**. Choose or upload a source video and a replacement character image from the same project. Select a clip start and processing size, save the draft, and Generate.

This integrates the supplied `Darius_H3_BodySwap.zip` API graph. Its source preparation takes at most five seconds, rounds down to H3's `17n+5` grid at 24 fps, and trims to available source. A full five-second selection produces 107 frames (4.458 seconds). Size follows source orientation with fit/padding and the imported pixel/height limits; the other H3 modes' aspect, resolution and long-duration controls do not apply. The output retains source audio when present; a silent source remains valid.

The selected Ollama vision model describes only the replacement image. The imported structured appearance node assembles the fixed `body_swap` task prompt and releases Ollama before H3 sampling. This model is independent of the chat provider. Default: `robit/ornith-vision:9b`. Ollama must be running and that vision model (or your selected compatible vision model) must already be installed.

The primary result is the swapped video. History also retains the matching prepared source under **Source comparison**. These are separate declared outputs, not two stages of an upscale. No new automatic generation, downloads, node installation or service restarts occur when switching modes or saving drafts.

The first-use dependency package includes the supplied verified H3 weights and upstream node sources. The ZIP provides no public repository URL for **ComfyUI-Darius-Recast** or **ComfyUI-Darius-Ollama**. Those author-supplied packs must already be installed in ComfyUI. Their runtime Python/text files must match the reviewed source hashes, and ComfyUI must report their loaded class ownership, before they can be reused outside Git provisioning. Reuse receipts are invalidated when files change. Missing or differing packs are reported rather than assigned invented download URLs. BiRefNet uses the imported RMBG node's own model preparation. Other ComfyUI revisions follow the same Block Party preparation flow as other boards.

Development junctions are supported for these two reviewed packs. Darius records the resolved location as a digest and invalidates readiness if that target changes. Because the pinned Block Party runtime's Git inventory excludes such junctions, Darius performs the final local readiness checks: unchanged contract, exact upstream Git revisions, complete model hashes, loaded nodes, runtime requirements, and renewed source/ownership receipts. It does not create a fictitious Block Party Git-preparation receipt for the local packs. Dependency downloads and upstream node installation still use Block Party's reviewed plan and provisioning flow.

Pinned template and source hashes are in `workflows/canvas/minimax-h3-body-swap-v1/manifest.json`. Imported personal upload filenames are removed from the checked-in graph; the original ZIP is identified by SHA-256. Each run binds project-owned immutable asset versions and records its media receipts, selected model, trim and processing size.
